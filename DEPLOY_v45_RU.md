# Kitobkhona v45 — кэш, активность и админ-инструменты

Архив содержит только изменённые файлы с сохранёнными путями. Версия является накопительной и включает необходимые актуальные файлы v44–v45.

## Порядок публикации

### 1. Neon / Render backend

Рекомендуется выполнить в Neon SQL Editor:

```text
kitobkhona-chat/OPERATIONS_CACHE_ACTIVITY_MIGRATION.sql
```

Затем скопировать backend-файлы и сделать deploy Render:

```text
kitobkhona-chat/server.js
kitobkhona-chat/RECOVERY_DATABASE.sql
kitobkhona-chat/OPERATIONS_CACHE_ACTIVITY_MIGRATION.sql
```

`server.js` также создаёт новые колонки и таблицы автоматически. SQL-миграция нужна как явный и проверяемый способ подготовить БД до первого запроса.

### 2. Cloudflare Worker

В этой версии новых изменений Worker для кэша нет. В архиве оставлены актуальные файлы Worker из v44, чтобы пакет был накопительным. Если v44 уже развёрнут, повторный deploy Worker необязателен.

### 3. GitHub Pages frontend

Скопировать содержимое папки `kitobkhona/` по тем же путям и опубликовать GitHub Pages.

PWA cache: `kitobkhona-v45`.

## Единый PDF-кэш

- Reader, «Скачать» и «Поделиться» вызывают один менеджер PDF.
- Первый запрос загружает PDF в `kitobkhona-pdf-cache-v1`.
- Следующие действия используют сохранённый Blob без повторного скачивания.
- Одновременные запросы одного PDF объединяются.
- Обычное обновление Service Worker больше не удаляет PDF.

## Команды кэша в админ-панели

Раздел `11 — Управление кэшем`:

1. **Обновить программу и данные** — удаляет страницы и временные данные, но сохраняет PDF, авторизацию, настройки и прогресс чтения.
2. **Очистить только PDF** — удаляет только сохранённые PDF и их список.
3. **Полная очистка** — объединяет первые две команды.

Команда проверяется при запуске, возвращении в приложение и каждые 10 минут. В админ-панели показывается число клиентов, сообщивших о применении версии.

## Неактивные аккаунты

Раздел `12 — Неактивные`:

- периоды 1, 2, 3, 4, 6, 9 и 12 месяцев;
- просмотр временных или всех аккаунтов;
- статистика по периодам;
- массовое удаление разрешено только для выбранных временных аккаунтов;
- обычные аккаунты в массовом режиме удалить невозможно;
- администраторы исключены.

`last_active_at` обновляется при входе и использовании защищённых API. Для старых данных дополнительно учитываются чтение, сообщения и публикации.

## Безопасный обзор БД

Раздел `13 — База данных` показывает:

- количество строк;
- размер таблиц;
- предпросмотр только разрешённых полей.

Пароли, JWT, reset-коды, email пользователей, push-токены, содержание личных сообщений и произвольный SQL не показываются.

## Авторские права и выделение текста

В пользовательском интерфейсе отключено случайное выделение при долгом нажатии. Ввод и редактирование в `input`, `textarea` и редакторах сохранены.

Добавлено уведомление:

```text
© 2026 Sharipov. Права на программу и дизайн защищены.
Права на книги принадлежат их авторам и правообладателям.
```

Важно: браузерная защита от выделения уменьшает случайное копирование, но технически не может полностью запретить скриншоты или получение уже переданного устройству материала.
