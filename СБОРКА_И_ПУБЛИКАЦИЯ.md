# Сборка, проверка и публикация Китобхона

Краткая рабочая инструкция. Всё, что раньше было размазано по десяткам файлов
`DEPLOY_v*.md` и `ИЗМЕНЕНИЯ_v*.md`, собрано здесь.

---

## 1. Что лежит в репозитории

| Проект | Назначение | Где |
|---|---|---|
| `kitobkhona/` | Сайт и PWA (этот репозиторий) | корень |
| `kitobkhona-chat/` | Node.js API чата и пользовательских функций | отдельный репозиторий |
| `kitobkhona-edge/` | Cloudflare Worker API | отдельный репозиторий |
| `kitobkhonaapp/` | Android WebView-приложение (Kotlin) | отдельный репозиторий |

Здесь только веб-часть. Сборка APK здесь **невозможна** — исходников Android
проекта в этом репозитории нет.

### Файлы, без которых не работает сохранение PDF

Кнопки «PDF» и «Word» под ответами Алии собирают документ в браузере. Для
PDF нужны эти файлы — они лежат в репозитории и **обязательно** должны попасть
на хостинг (иначе PDF не соберётся, особенно офлайн):

| Файл | Зачем |
|---|---|
| `assets/libs/pdf-lib.min.js` | сборка PDF |
| `assets/libs/fontkit.umd.min.js` | встраивание шрифтов |
| `assets/fonts/NotoSans-Regular.sub.ttf` | основной шрифт |
| `assets/fonts/NotoSans-Bold.sub.ttf` | полужирный |
| `assets/fonts/NotoSans-Italic.sub.ttf` | курсив |
| `assets/fonts/DejaVuSym.sub.ttf` | знаки, которых нет в Noto |

Все шесть файлов внесены в `LOCAL_FILES` в `sw.js`, поэтому после первого
открытия PDF собирается и без интернета.

## 2. Проверки (обязательно перед публикацией)

```bash
npm install
npm run test:fixes
```

`test:fixes` запускает восемь наборов:

| Команда | Что проверяет |
|---|---|
| `npm run test:aliya` | Контракты Алии: форматы запросов, OCR, DOCX, PDF-экспорт, изоляция ключа ученического теста |
| `npm run test:reader` | Перелистывание в читалке, панели, таймер скрытия, контроллер curl |
| `npm run test:reader-aliya` | Экспорт ответов Алии в Reader: Word и **настоящий** PDF (реальные библиотеки и шрифты) |
| `npm run test:reader-zoom` | Тема читателя в одно нажатие и свободный зум (выполняется реальный код `reader.html`) |
| `npm run test:latency` | Тайм-аут, число попыток, `reasoning_mode`, бюджет панели |
| `npm run test:gateway` | Каждый маршрут шлюза ограничен общим дедлайном |
| `npm run test:html` | Разметка и синтаксис: версии ассетов, precache, отсутствие мёртвых копий |
| `npm run test:ui` | Адаптивность, навигация, iframe Reader → Алия |

Отдельный набор:

```bash
npm run test:reader-aliya   # только экспорт Алии
npm run test:reader-zoom    # только тема и зум
```

## 3. Service Worker и обновление пользователей

**Главное правило:** Service Worker кеширует `.js` и `.css` по ключу **без
учёта query-строки** (`cache.match(request, { ignoreSearch: true })`).
Поэтому `?v=172`, `?v=161` и `?v=177` — это **один и тот же** ключ кеша.
Префикс `?v=` сам по себе кеш не сбивает.

Обновляет ассет только новый `CACHE_NAME`:

1. в `sw.js` меняем `CACHE_NAME` (например `kitobkhona-v177-aliya-reader-save-pdf`);
2. при `activate` старые versioned-кэши удаляются по шаблону
   `/^kitobkhona-v\d+[-\w]*$/`, новый заполняется заново при `install`;
3. `?v=` в `<script src=...>` поднимаем **до той же цифры**, что и в `CACHE_NAME`.

Это проверяется тестом `tests/check_aliya_html.py`: если версия в `?v=` не
совпадёт с `CACHE_NAME`, тест упадёт с понятным сообщением.

## 4. Порядок публикации

1. Прогнать `npm run test:fixes` — всё должно быть зелёным.
2. Разложить изменённые файлы на хостинг **с сохранением путей** (`assets/`,
   `aliya/` объединяются с существующими).
3. `sw.js` публиковать **последним** — иначе старый worker продолжит отдавать
   старый кэш.
4. Не менять URL приложения и scope Service Worker без отдельного плана.
5. Для `sw.js` настроить revalidation / `no-cache`, если хостинг позволяет.
6. Проверить, что у всех файлов нет 404, MIME для JS/CSS корректные, сайт
   открывается по HTTPS.

### Чего не делать

- очищать `localStorage`, прогресс чтения, кэш скачанных книг;
- удалять `kitobkhona-pdf-cache-v1` (скачанные книги);
- требовать от пользователя переустановку приложения — достаточно штатного
  обновления PWA.

## 5. Windows-сборка (Electron)

```bash
npm install
npm run dist:win
```

Локальный безопасный HTTP-сервер обслуживает статические файлы, Electron
renderer работает без Node-доступа и с включённой изоляцией контекста.

Workflow `.github/workflows/build-windows-exe.yml` публикует сборку как Actions
artifact; при push-теге вида `v*` дополнительно прикладывает
`Kitobkhona-Setup.exe` к GitHub Release. **Пока тег не проставлен, ссылка
«Download» может не иметь опубликованного файла.**

Установщик в этой среде не запускался — его нужно проверить в GitHub Actions
на Windows до публикации.

## 6. Шлюз Алии: что осталось владельцу

Шлюз живёт отдельно (`aliya-gateway/app.py` в Space
`sharipovip/aliya-gateway`) и **не входит в этот репозиторий**. Изменения в нём
требуют собственных исходников и секретов.

Что нужно сделать владельцу Space:

1. В Hugging Face Space открыть provider diagnostics и восстановить ключи,
   доступы и баланс для каналов, которые использует именно чат. Наличие
   переменной окружения само по себе не означает успешный ответ.
2. После исправления повторить **реальный** `POST /v1/chat`, а не
   ограничиваться `GET /health`.
3. Типичные причины сбоя, которые видели: `403 no_access_to_model_or_provider`
   у ряда HF-моделей, `429 rate_limited` у Gemini, `402 insufficient_credits`
   у платных провайдеров.

**Это не исправляется изменением HTML.** Клиент после исправлений не маскирует
такой сбой — он сообщает причину пользователю.

## 8. Контрольные проверки перед публикацией

- три темы читателя (день / ночь), переключение **в одно нажатие**;
- свободный зум страницы: пинч двумя пальцами, панорамирование, диапазон
  50 %–400 %, текст остаётся резким;
- Алия в читалке: у **каждого** ответа есть рабочие кнопки «Word» и «PDF»,
  файл реально сохраняется;
- главная, каталог, профиль, социальные страницы, возврат из Алии;
- сохранённые книги и прогресс чтения не пострадали;
- повторный заход в офлайн.

Отдельно и **только на тестовом аккаунте**: вход, отправка/получение
сообщения, AI-ответ, экспорт файла, push-уведомления.

> Браузерная проверка не заменяет проверку на телефоне. Если что-то выглядит
> иначе — зафиксируйте URL, версию установленного APK/WebView, экран, тему и
> действие.
