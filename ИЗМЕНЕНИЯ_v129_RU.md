# Китобхона — обновление v129 (PWA 3.1.3 · Edge 2.3.2 · sw `kitobkhona-v129-fast-nav`)

Дата: 16.10.2026. Правки поверх v128 (ниже — описание v128, v127 и v126). **В архиве — только изменённые/
добавленные файлы** относительно исходной загрузки «Китобхона новая версия до 10 октября» (сравнение по
SHA‑256), со структурой папок — распаковать поверх репозиториев. Список — в `СПИСОК_ФАЙЛОВ.txt`.
PDF тавсия — в отдельном `kitobkhona_tavsiya_pdf.zip` (не менялись).

### Что изменено

1. **Ключ Supabase (`config.js` → `SUPABASE_KEY`).** Присланный ключ **побайтово совпадает** с тем, что уже стоит в
   `config.js`, и он **рабочий**: проверка `GET /rest/v1/profiles?select=*&limit=1` с этим ключом → `200` и данные;
   `/auth/v1/settings` → `200`. Мой вывод из анализа v1 («ключ невалидный») был ошибкой: я проверял корень
   `/rest/v1/`, который Supabase теперь отдаёт только по `service_role` (ответ так и говорит: «Only the
   service_role API key can be used for this endpoint»). Ключ в `config.js` не менялся. Исправлены оба keep‑alive,
   чтобы они делали **реальный запрос к таблице** (`/rest/v1/profiles?select=id&limit=1`), а не к OpenAPI‑корню:
   `kitobkhona-edge/src/keepalive.ts` (Edge 2.3.2) и `.github/workflows/supabase-keepalive.yml`
   (+ `/auth/v1/settings`, который работает с anon‑ключом). Секрет `SUPABASE_KEEPALIVE_KEY` в GitHub можно задать
   этим же anon‑ключом — тогда резервный пинг будет авторизованным.
2. **Главная — «Китобҳои захирашуда».** Над карточкой убрана строка‑заголовок «📥 Китобҳои захирашуда · Идора кардан»
   (карточка сама ведёт на `offline-books.html` и показывает число книг, объём и статус). Три блока теперь идут
   подряд одной колонкой: маориф → хонандагон → захирашуда.
3. **Скорость и плавность — для всех страниц.**
   * **Заставка на старте** (`index.html`, `#startupSplash`): было принудительно 5–9 секунд, стало 1.5–4 с
     (показывается один раз за сессию, как и раньше). Константы `MIN`/`MAX` в том же месте — при желании вернуть.
     В headless‑Chromium заставка исчезает через ~2.2 с после начала загрузки (было ≥5 с).
   * **Переходы между страницами** (`sw.js`): раньше каждая навигация ждала сеть до **3.5 с** (network‑first); теперь,
     если страница есть в кэше, сеть ждём **≤ 600 мс** — на хорошем интернете приходит свежая страница, иначе
     мгновенно отдаётся кэш, а сеть обновляет кэш в фоне (следующий заход — уже новая). Без кэша — как раньше
     (сеть, затем `offline.html`). Для публичных JSON/API окно 2.5 с → 1.8 с; `news.json` при медленной сети отдаёт
     кэш через 3 с вместо бесконечного ожидания. Проверено юнит‑тестом fetch‑обработчика (6 сценариев).
   * **Уведомление о новой версии** (`config.js`): когда новый `sw.js` берёт страницу под управление, внизу
     появляется плашка «Версияи нави Китобхона омода аст — Навсозӣ» (25 с, можно закрыть). Это страховка для
     случая, когда страница пришла из кэша: пользователь не останется на старой версии «молча». Первая установка
     SW плашку не показывает.
   * **Плавные переходы страниц**: `@view-transition { navigation: auto }` (cross‑document View Transitions,
     Chrome/Android WebView 126+; в остальных браузерах просто нет эффекта) — вместо белой вспышки между страницами
     короткое (0.18 с) затухание; старая страница остаётся на экране, пока новая не готова к отрисовке.
     Отключается при `prefers-reduced-motion` и в лёгком режиме.
   * **Лёгкий режим для слабых телефонов** (`html.kk-lite`: ≤ 2 ГБ RAM, ≤ 2 ядра, Data Saver или 2G): отключаются
     `backdrop-filter`‑размытия (главный источник подтормаживаний при прокрутке на бюджетных Android) и анимация
     переходов. На обычных устройствах ничего не меняется.
   * `touch-action: manipulation` для кнопок/ссылок/полей (без задержки двойного тапа в WebView), прозрачный
     tap‑highlight и `preconnect` к Edge‑воркеру, Vercel‑прокси и raw.githubusercontent.com (первый запрос к API и
     обложкам на 100–300 мс быстрее) — одним блоком в `config.js`, поэтому действует на всех страницах.
   * **`Lenta.html`**: таблица стилей Google Fonts (15 семейств) больше не блокирует отрисовку (`preload` →
     `stylesheet` по загрузке, `noscript`‑запасной вариант, `preconnect` к `fonts.gstatic.com`) — страница
     рисуется сразу, шрифты подтягиваются следом. **`chat.html`**: `@import` шрифта из `<style>` (блокирующий)
     заменён тем же неблокирующим `<link>` в `<head>`.
   * `index.html`: часы в шапке не обновляют DOM, пока вкладка скрыта.
   * Уже было хорошо и не трогалось: пакетный рендер библиотеки по 48 карточек, `loading="lazy"` у обложек,
     пассивные touch‑обработчики, ограничение DPR ≤ 2 в читалке PDF, cache‑first для JS/CSS/картинок.
4. **Версии:** `APP_VERSION` 3.1.3, `config.js?v=75` во всех 15 страницах, `sw.js`
   `CACHE_NAME = 'kitobkhona-v129-fast-nav'`, Edge 2.3.2 (`npx wrangler deploy`). `server.js` относительно v128 не
   менялся (деплой на Render нужен, если v128 ещё не выкладывали).

### Проверка

     после закрытия;

     домен»** со спиннером, подсказкой «сомонаҳои давлатӣ баъзан суст бор мешаванд», кнопкой
     «Дар браузер кушодан» (внешний браузер через `AndroidBridge.openExternalUrl`) и «Бекор кардан».
     Индикатор исчезает сам при уходе со страницы (`pagehide`) или через 20 с (если WebView по
     какой-то причине не перешёл, например домен не в allow-list приложения).
   * В браузере/PWA поведение прежнее — мини-браузер открывается мгновенно, индикатор не нужен.
   * Замечание по Android-коду (не менялся): в `MainActivity.kt` → `openOfficialSiteInApp` для
     неразрешённого домена создаётся `Toast.makeText(...)`, но не вызывается `.show()` — пользователь
     ничего не видит. Стоит добавить `.show()` при следующей сборке APK.
4. **Фоновые запросы — аудит и правки (чтобы бесплатные часы Render/Neon не сгорали впустую).**
   Проверены все `setInterval`/`setTimeout`/cron во всех HTML, `config.js`, `sw.js`, `server.js`,
   Edge-воркере и GitHub Actions. Итог — см. таблицу ниже; исправлено:
   * **`kitobkhona-chat/server.js`:** убран опрос Neon каждые 60 с (`flushPendingNotificationPushes`
     по `setInterval`). Он не давал Neon заснуть всё время, пока Render бодрствует (Neon засыпает после
     5 мин тишины, Render — после 15 мин без запросов; из-за таймера каждое пробуждение Render стоило

     процесса; «попутно» не чаще 1 раза в 5 мин — только при запросах реальных пользователей
     (с токеном; health-check/мониторинг базу не трогают); и по сигналу Edge — новый
     `POST /api/notifications/flush-push` (не чаще 1 раза в минуту).
   * **Edge (`notify.ts`, `public-api.ts`, `reading-sync.ts`):** после создания уведомлений
     (победители рейтинга 1–3, рубеж 50 часов) воркер сам дёргает `flush-push` на Render
     (`requestPushFlush`, таймаут 8 с, через `ctx.waitUntil`). Если Render спал — этот же запрос его
     будит, и стартовая обработка через 15 с отправит push; ошибка/таймаут пинга не критичны.
     Версия Edge 2.3.1 (нужен `npx wrangler deploy`).

     видимой странице и онлайн.

   **Таблица фоновой активности после v128**

# Китобхона — обновление v126 (PWA 3.1.0 · Edge 2.3.0 · Render server)

Дата: 15.10.2026. Все изменения сделаны в 4 репозиториях из исходного архива.
Папки в этом архиве полностью повторяют структуру репозиториев — файлы можно копировать поверх.

| Папка | Что это | Изменено |
|---|---|---|
| `kitobkhona/` | PWA (GitHub Pages / Cloudflare Pages) | да — основная часть |
| `kitobkhona-chat/` | Node/Express сервер на Render (чат, push, уведомления) | да — `server.js` |
| `kitobkhona-edge/` | Cloudflare Worker (публичный API, рейтинг, синхронизация чтения) | да — `src/*.ts`, `sql/` |
| `kitobkhonaapp/` | Android-обёртка (Capacitor) | **без изменений** (нативный мост уже поддерживает всё нужное) |

> Архив `kitobkhona_tavsiya_pdf.zip` (76 МБ) — 30 PDF-книг для раздела «Адабиёти тавсияшуда».
> Распаковать в ту же папку: получится `kitobkhona/tavsiya/pdf/*.pdf`. Без него раздел работает,
> но ссылки «Кушодан» у 30 позиций с локальными PDF будут вести в никуда. Эти PDF при желании можно
> перенести в репозиторий `books` и поправить поле `match.url` в `data/tavsiya.json` (скрипт сборки
> делал абсолютные пути вида `tavsiya/pdf/<файл>.pdf` относительно корня PWA).

## 1. index.html — работа без интернета
* `sw.js`: новый кэш `kitobkhona-v126-tavsiya-offline`. В предкэш добавлены новая страница,
  `data/tavsiya.json`, `data/contests.json`, тексты `tavsiya/matn/*.json` и все 100 фото цитат
  (`assets/hero/1..100.jpeg`).
* Новый runtime-кэш `kitobkhona-runtime-v1` (stale-while-revalidate, лимит 400 записей):
  JSON каталога с raw.githubusercontent/jsdelivr, публичные GET Edge-API (рейтинг, популярные книги,
  объявления), обложки/фото (flickr, weserv). Раньше эти ответы вообще не кэшировались — отсюда
  «пустые» секции офлайн.
* Навигация: гонка «сеть 3,5 с → кэш», чтобы при плохом интернете страница не висела.
* Файлы книг (PDF) в общий кэш не попадают — ими управляет существующий кэш читалки.
* `index.html`: `loadBooksJson()` и `loadManifest()` теперь «сначала кэш, потом сеть» с фоновым
  обновлением (события `kk-books-updated` / `kk-manifest-updated`), таймаут манифеста 5 с.
  Убран внедрённый Cloudflare-скрипт аналитики (внешний модуль, падал офлайн).
* `books.json` в репозитории заменён актуальным (53 категории) — он же используется как офлайн-резерв.

## 2. Новости — во внутреннем браузере
* `newsOpen()` больше не вызывает внешний браузер: ссылки открываются в мини-браузере приложения
  (`openMiniBrowser(..., keepInApp=true)`), а для правительственных доменов — в `openGovernmentSite`
  (тот же in-app WebView в Android-обёртке).

## 3. Уведомления (победители, 50 часов, аватар) и «Озмунҳои ҷумҳуриявӣ»
Схема: уведомления хранятся в таблице `user_notifications` (Neon). Их создают и Edge, и Render;
Render раз в 60 с отправляет Web Push по строкам с `push_sent_at IS NULL`.
* **1/2/3 место** в рейтинге (общий / месяц / неделя): Edge `winners()` → `notifyTopReaders()`;
  Render `sendAchievementNotifications()` переписан. Текст: «🏆 Шумо ғолиб шудед — ҷойи N-ум!»,
  в теле — какое место и что открыт аватар. Дедупликация `top3:{period}:{stamp}:{place}`
  (общий рейтинг — один раз, месяц — раз в месяц, неделя — раз в неделю).
* **50 часов чтения**: Edge `reading-sync` и Render `POST /api/reading-sessions` при переходе через
  50 ч создают «🎉 50 соати хониш — аватар кушода шуд!» (`milestone:50h`, один раз).
* **Аватар за 1–3 место**: Edge уже разрешал (50 ч или top-3 all/month/week); Node-маршрут
  eligibility приведён к той же логике.
* Клиент: колокольчик в шапке показывается залогиненным, бейдж непрочитанных обновляется раз в 5 мин
  (`updateNotifBadge`), модалка показывает непрочитанные + последние 20 прочитанных, при открытии —
  «прочитать всё». `config.js`: реальные `getNotifications / markNotificationRead /
  markAllNotificationsRead` через `NEON_API_BASE`. Клик по push из `sw.js` открывает
  `winners.html` / `profile.html` относительно scope.
* API (Render): `GET /api/notifications`, `GET /api/notifications/unread-count`,
  `POST /api/notifications/read-all`, `PUT /api/notifications/:id/read`.
* **Конкурсы**: `data/contests.json` — расписание этапов 5 конкурсов (из низомнома в приложении и
  новостей khovar.tj). Если следующий этап начинается в течение 30 дней — на иконке конкурса
  зелёная точка с числом дней (идёт сейчас — «●»). Нажатие открывает лист: статус, все этапы
  (когда/где, прошедшие/текущий), кто может участвовать, как участвовать, контакты/официальные сайты
  (открываются во внутреннем браузере), кнопка к полному низомнома. Если все этапы года прошли,
  расписание переносится на год вперёд с пометкой «тахминӣ». На 15.10.2026: «Илм — фурӯғи маърифат»
  (финал 16–31 октября) — бейдж «1», «Фурӯғи субҳи доноӣ» (финал ноябрь) — «17».
  **Обновлять `data/contests.json` при выходе новых указов** (поле `updated`).

## 4. Цитаты Президента — 100 цитат + фото
* `quotes-data.js` (и копия `icons/quotes-data.js`): 42 → 100 цитат. Новые 58 взяты из текстов
  выступлений и посланий 2015–2026 через API controlpanel.president.tj, каждая проверена по полному
  тексту; поля `sourceTitle`, `sourceDate`, `source`, `photo`.
* `assets/hero/43..100.jpeg` — 58 фото с тех же мероприятий (flickr presidenttj), 720 px, 4,1 МБ.

## 5. Профиль — локальная статистика чтения, «Корбарон» без логина
* `config.js`: `KKReadingLog` (localStorage `kk_reading_log_v1`) — пишет каждую сессию чтения
  локально (обёртка над `KKReadingSyncV2.add`), `summary(days)` считает часы, книги, завершённые,
  активные дни, серию дней подряд, по дням/месяцам/дням недели, топ книг, лучший день.
* `profile.html`: карточка «Омори хониш» (7 дней / 30 дней / год) со столбчатыми SVG-диаграммами,
  днями недели и топ-книгами — всё считается локально. При входе в аккаунт история из
  `/api/reading-sessions?user_id=&limit=1000` импортируется в локальную базу (слияние по
  «день+книга», берётся максимум) — раз в 6 ч или кнопкой «Навсозӣ аз ҳисоб».
* «Корбарон»: логин больше не показывается и не отдаётся API (Edge `directory.ts`, Render
  `/api/users/directory-public`) — только имя, фамилия, пол, год рождения, регион/город.

## 6. «Китобҳои зеркашидашуда» — Мубодила и сохранение в память
* `offline-books.html`: «Мубодила» берёт файл книги из кэша и делится им (`shareFile`, как в
  reader.html); рядом новая кнопка «💾 Ҳифз дар хотира» — сохраняет файл из кэша в память телефона
  (`downloadFile`, через нативный мост в Android / `<a download>` в браузере).

## 7. Новая страница «Адабиёти тавсияшуда» (1–11 классы)
* В главном ряду категорий добавлена строка (`#tavsiyaRow`) → `adabiyoti-tavsiyashuda.html`.
* `data/tavsiya.json`: 296 позиций из PDF «Рӯйхати адабиётҳои тавсияшуда» (по классам, основной
  список + летнее чтение), с опечатками исходника исправленными. Для каждой позиции — результат
  поиска по каталогу приложения:
  * `exact` 114 — книга есть в каталоге → «Кушодан» открывает в reader.html;
  * `part` 18 — произведение входит в книгу каталога (указано, в какой);
  * `related` 76 — в каталоге нет, но найден сборник/PDF (30 PDF из открытого архива zarowadk.com,
    серия «Афсонаҳои халқи тоҷик» ҷ. 1–6, 2016 и др.) — открываются в reader.html;
  * `text` 6 — отдельные сказки (Пушкин, Перро, Афанасьев, Гримм…) — текст из Wikisource читается
    во встроенной читалке (A−/A+, тёмная/сепия/светлая тема, прогресс, учёт времени чтения);
  * `none` 82 — не найдено ни в каталоге, ни в надёжных открытых источниках (в основном современные
    русские книги с авторскими правами) — показана подсказка, где искать (Маориф, библиотека, kmt.tj).
* Страница работает офлайн (предкэш), есть поиск, фильтры по типу, чипы классов, нижний лист с
  описанием и источниками.

4. **PWA**: залить папку `kitobkhona/` (+ PDF из второго архива в `kitobkhona/tavsiya/pdf/`).
   Сервис-воркер обновится сам (новое имя кэша v126).

## Ограничения / на что обратить внимание
* Расписание «Тоҷикистон — Ватани азизи ман» на 2026 г. — по низомнома 2025 г. (помечено «тахминӣ»).
* 82 позиции списка не найдены в открытых источниках — для них даны подсказки.
* Уведомления о победе создаются при пересчёте рейтинга (`/api/winners` на Edge — при промахе кэша,
  Render — по своему расписанию); push приходит в течение ~1 мин после создания записи.
* Из отчёта фазы 1 остаются открытыми: защита рейтинга от накрутки, модерация чата, `CRON_SECRET`,
  утечки `details:e.message` в ответах ошибок.
