# Диагностика доступности шлюза Алии · снимок 12 ноября 2026

Проверена только публичная часть шлюза `sharipovip/aliya-gateway`; секреты не запрашивались, не печатались и не изменялись.

- Hugging Face Space отвечает и в момент проверки имел runtime `RUNNING`; `/health?deep=1` сообщал `chat_ready=true`. Этот общий флаг не подтверждает, что конкретный запрос пользователя будет обслужен.
- Прямой тест `/v1/chat` на коротком вопросе на таджикском вернул HTTP 200, но пустой `reply` и `error=chat_providers_unavailable` примерно через 11.3 секунды. В ответе диагностики для этого вызова шесть моделей HF Router имели HTTP 403 (`no_access_to_model_or_provider`), а два проверенных маршрута SambaNova — HTTP 402 (`insufficient_credits`).
- В предыдущем deep-probe того же публичного Space Gemini и Z.ai вернули HTTP 429, а шесть HF Router probes — HTTP 403. Это наблюдения на момент проверки, не гарантия постоянного состояния и не доказательство отказа абсолютно всех маршрутов.
- Публичный код шлюза действительно запускает последовательные маршруты: Gemini, дополнительные OpenAI-совместимые провайдеры, ZeroGPU, затем HF Router. Поэтому фронтенд не может устранить исчерпание кредитов, ошибки прав доступа или лимиты провайдера; для этого владелец должен проверить конфигурацию сервера и права/лимиты в соответствующих панелях.
- В клиенте убраны повторные одинаковые вызовы после ответа `chat_providers_unavailable` (gateway уже перебрал настроенные fallback-маршруты). Временные ошибки сети/5xx и тайм-ауты допускают одну повторную попытку; при конечном отказе вопрос остаётся в истории и пользователь может явно нажать «Дубора фиристодан».

Никакие backend-файлы удалённого Space в этом комплекте не редактировались и не развёртывались. Клиентское изменение само по себе не обещает, что все модели будут доступны.
